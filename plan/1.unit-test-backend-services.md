## 1. Setup & Konfigurasi

### 1.1 Instalasi Dependencies

```bash
cd backend
npm install --save-dev @nestjs/testing
```

> NestJS sudah include Jest secara default. Jika belum ada, jalankan:
> ```bash
> npm install --save-dev jest @types/jest ts-jest
> ```

### 1.2 Konfigurasi Jest

Tambahkan ke `backend/package.json` (jika belum ada):

```json
{
  "jest": {
    "moduleFileExtensions": ["js", "json", "ts"],
    "rootDir": "src",
    "testRegex": ".*\\.spec\\.ts$",
    "transform": { "^.+\\.(t|j)s$": "ts-jest" },
    "collectCoverageFrom": [
      "**/parsers/*.parser.ts",

## 2. Konvensi & Pola Testing

### Pola Penamaan

```typescript
describe('[NamaService]', () => {
  describe('namaMethod()', () => {
    it('should [expected behavior] when [condition]', () => {});
    it('should throw [Exception] when [error condition]', () => {});
  });
});
```

### Pola Mock Service

```typescript
import { Test, TestingModule } from '@nestjs/testing';

describe('ExampleService', () => {
  let service: ExampleService;
  let mockDependency: jest.Mocked<DependencyService>;

  beforeEach(async () => {
    const mockDep = {
      someMethod: jest.fn(),
    };

    const module: TestingModule = await Test.createTestingModule({
      providers: [
        ExampleService,
        { provide: DependencyService, useValue: mockDep },
      ],
    }).compile();

    service = module.get(ExampleService);
    mockDependency = module.get(DependencyService);
  });

  afterEach(() => jest.clearAllMocks());
});
```

## 8. Yang SENGAJA Tidak Di-test

| Module / Method | Alasan Skip |
|---|---|
| **CRUD wrappers** (`findAll`, `findById`, `create`, `remove` yang hanya forward ke repository) | Wrapper tipis tanpa business logic — Prisma sendiri sudah tested |
| **AdminService.getStats()** | Hanya `count()` dan `aggregate()` — zero business logic |
| **MailService** | Wrapper nodemailer — lebih cocok integration test atau manual test |
| **NotificationsService** | Wrapper web-push — lebih cocok integration test |
| **OCR Service** | Bergantung Tesseract.js (external lib) — sulit di-unit-test tanpa mock berat |
| **BankStatementsService** (CRUD methods) | `findAll`, `findOne` hanya forward ke repo — yang ditest adalah **parsers** |
| **UsersService** (most methods) | CRUD wrapper ke `UsersRepository` |
| **CategoriesService** | Logic sederhana, edge case minimal |
| **Reports Repository** | Raw SQL — lebih cocok integration test dengan database nyata |
| **Guards, Filters, Interceptors** | Trivial implementations, NestJS framework handles most logic |

> **Prinsip**: Jika suatu method **hanya meneruskan data ke layer lain tanpa transformasi atau keputusan**, maka test-nya memberikan nilai yang rendah. Fokus test pada method yang **mengambil keputusan bisnis** (if/else, kalkulasi, validasi).
