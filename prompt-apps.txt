================================================================================
PROMPT: APLIKASI MONEY MANAGEMENT - FULL-STACK WEB APPLICATION
================================================================================

Buatkan aplikasi Money Management berbasis web untuk mengatur keuangan pribadi
dengan arsitektur frontend dan backend yang terpisah (decoupled architecture).
Aplikasi ini harus production-ready, mengikuti prinsip Clean Code, SOLID,
dan dikembangkan dengan pendekatan TDD (Test-Driven Development).

================================================================================
1. TECH STACK
================================================================================

FRONTEND:
- Framework       : Next.js 15 (App Router)
- Language         : TypeScript (strict mode)
- Styling          : Tailwind CSS v4
- UI Components    : Shadcn UI (latest)
- State Management : TanStack Query v5 (untuk server state)
- Form Handling    : React Hook Form + Zod (untuk validasi)
- Chart            : Recharts atau Chart.js (untuk dashboard & laporan)
- PWA              : next-pwa / @serwist/next (untuk Progressive Web App)
- HTTP Client      : Axios (dengan interceptor untuk auth token)
- Date Handling    : date-fns atau dayjs
- PDF Viewer       : react-pdf (untuk preview e-statement)
- Testing          : Jest + React Testing Library + Playwright (E2E)

BACKEND:
- Framework        : NestJS (latest, modular architecture)
- Language          : TypeScript (strict mode)
- Database         : PostgreSQL 16+
- ORM              : Prisma (latest)
- Authentication   : Passport.js + JWT (access token + refresh token)
- Validation       : class-validator + class-transformer
- API Docs         : Swagger / OpenAPI (@nestjs/swagger)
- File Upload      : Multer (@nestjs/platform-express)
- OCR Engine       : Tesseract.js atau Google Cloud Vision API
- PDF Parsing      : pdf-parse / pdf2json (untuk e-statement bank)
- Job Queue        : BullMQ + Redis (untuk background jobs: OCR, PDF parsing, reminder)
- Email/Notif      : Nodemailer atau @nestjs-modules/mailer (untuk reminder)
- Push Notif       : web-push (untuk PWA push notification)
- Caching          : Redis (@nestjs/cache-manager)
- Rate Limiting    : @nestjs/throttler
- Testing          : Jest + Supertest (integration) + unit tests
- Logging          : Winston atau Pino

INFRASTRUCTURE & DEVOPS:
- Containerization : Docker + Docker Compose
- CI/CD            : GitHub Actions
- Linting          : ESLint + Prettier (shared config untuk mono-standards)
- Git Hooks        : Husky + lint-staged + commitlint (conventional commits)
- Environment      : dotenv / @nestjs/config

----------------------------------------------------------------------
4.1 AUTENTIKASI (Login & Registrasi)
----------------------------------------------------------------------
- Registrasi user baru dengan email, nama, dan password.
- Password di-hash menggunakan bcrypt (min 8 karakter, harus ada huruf besar,
  huruf kecil, angka, dan karakter spesial).
- Login menggunakan email + password, mengembalikan:
  - Access Token (JWT, expired 15 menit)
  - Refresh Token (JWT, expired 7 hari, disimpan di httpOnly cookie)
- Endpoint refresh token untuk mendapatkan access token baru.
- Endpoint logout untuk invalidate refresh token.
- Implementasikan rate limiting pada endpoint auth (max 5 percobaan per menit).
- Frontend: Simpan access token di memory (bukan localStorage), refresh token
  via httpOnly secure cookie.
- Middleware Next.js untuk redirect user yang belum login ke halaman login.
- Role-based access: Admin bisa akses halaman admin, User tidak bisa.

----------------------------------------------------------------------
4.2 DASHBOARD
----------------------------------------------------------------------
- Ringkasan keuangan: Total pemasukan, total pengeluaran, saldo saat ini
  (bulan berjalan).
- Chart pemasukan vs pengeluaran (line chart atau bar chart) - 6 bulan terakhir.
- Pie chart / donut chart breakdown pengeluaran per kategori (bulan berjalan).
- List 5-10 transaksi terakhir.
- Progress bar budget per kategori (bulan berjalan).
- Widget reminder yang akan jatuh tempo dalam 7 hari ke depan.
- Card ringkasan: perbandingan bulan ini vs bulan lalu (naik/turun dalam %).
- Responsive: mobile-first design, cards stack vertically pada mobile.
- Data di-fetch menggunakan TanStack Query dengan caching dan background refetch.

----------------------------------------------------------------------
4.3 TRANSAKSI (Income & Expense)
----------------------------------------------------------------------
- CRUD transaksi (Create, Read, Update, Delete).
- Setiap transaksi memiliki: jumlah, tipe (INCOME/EXPENSE), kategori, tanggal,
  deskripsi, catatan opsional.
- Form input dengan validasi real-time (Zod + React Hook Form).
- Input mata uang dengan format Rupiah (Rp 1.000.000).
- Tabel transaksi dengan:
  - Pagination (server-side)
  - Sorting (berdasarkan tanggal, jumlah)
  - Filter (berdasarkan tipe, kategori, rentang tanggal)
  - Search (berdasarkan deskripsi)
- Bulk delete transaksi (pilih beberapa, lalu hapus sekaligus).
- Export transaksi ke CSV/Excel.
- Transaksi bisa memiliki lampiran struk (foto).
- Soft indicator pada transaksi yang berasal dari OCR atau bank import.

4.8 OCR - BACA STRUK BELANJA
----------------------------------------------------------------------
- User upload foto struk belanja (JPG, PNG, HEIC).
- Backend memproses gambar menggunakan Tesseract.js atau Google Cloud Vision.
- Parsing hasil OCR untuk mengekstrak:
  - Nama toko / merchant
  - Tanggal transaksi
  - Item-item belanja (nama item + harga)
  - Total pembayaran
- Tampilkan hasil OCR di frontend untuk user review & edit sebelum disimpan
  sebagai transaksi.
- User bisa mengoreksi hasil parsing yang salah.
- Setelah dikonfirmasi, otomatis buat transaksi EXPENSE dengan:
  - Jumlah = total dari struk
  - Kategori = user pilih atau auto-suggest berdasarkan merchant
  - Source = OCR
- Proses OCR berjalan di background (BullMQ) untuk file besar.
- Tampilkan status processing (pending, processing, completed, failed).
- Simpan gambar struk yang sudah di-upload sebagai lampiran transaksi.

----------------------------------------------------------------------
4.9 BACA E-STATEMENT BANK (PDF)
----------------------------------------------------------------------
Mendukung 4 bank berikut:
- Bank Permata
- Bank Jago
- Sea Bank
- Bank BCA

Alur kerja:
1. User pilih bank dari dropdown.
2. User upload file PDF e-statement.
3. Backend mem-parsing PDF menggunakan pdf-parse/pdf2json.
4. Setiap bank memiliki parser khusus (Strategy Pattern / Factory Pattern):
   - Setiap parser memahami format PDF masing-masing bank.
   - Extract data: tanggal, deskripsi, debit, kredit, saldo.
5. Tampilkan daftar transaksi hasil parsing di frontend.
6. User review, edit, dan pilih mana yang ingin di-import.
7. User bisa memilih kategori untuk setiap transaksi atau batch assign.
8. Setelah dikonfirmasi, buat transaksi-transaksi baru dengan source = BANK_IMPORT.

Persyaratan parser:
- Gunakan base abstract class `BaseStatementParser` yang memiliki method:
  - parse(buffer: Buffer): ParsedStatement
  - validate(buffer: Buffer): boolean
  - getBankName(): BankName
- Setiap bank punya class parser sendiri yang extend base class.
- Factory class untuk memilih parser berdasarkan bank yang dipilih user.
- Handle edge cases: password-protected PDF, format tidak dikenal, data corrupt.
- Proses parsing berjalan di background (BullMQ).
- Simpan file PDF original dan track status processing.
- Unit test untuk setiap parser dengan sample PDF.

4.10 ROLE-BASED ACCESS CONTROL (RBAC)
----------------------------------------------------------------------
ROLE: USER
- Akses ke semua fitur personal (dashboard, transaksi, budget, laporan,
  reminder, scan, import).
- Hanya bisa melihat dan mengelola data milik sendiri.

ROLE: ADMIN
- Semua akses User.
- Dashboard admin: statistik pengguna, total transaksi platform.
- Manajemen user: lihat daftar user, nonaktifkan user, ubah role user.
- Lihat analytics keseluruhan platform (tanpa detail transaksi user).
- Manage kategori default (CRUD kategori bawaan sistem).

Implementasi:
- Custom decorator @Roles('ADMIN', 'USER') pada controller.
- RolesGuard untuk mengecek role user di setiap protected endpoint.
- Frontend: conditional rendering berdasarkan role user.
- Middleware/guard di Next.js untuk proteksi halaman admin.

6. PRINSIP DEVELOPMENT
================================================================================

CLEAN CODE:
- Meaningful variable dan function names (deskriptif, tidak ambigu).
- Single Responsibility: setiap function/class hanya melakukan satu hal.
- DRY (Don't Repeat Yourself): hindari duplikasi kode, buat utility functions.
- Consistent code style (ESLint + Prettier).
- Maximum function length: ~20-30 baris. Jika lebih, refactor ke fungsi kecil.
- Meaningful comments hanya untuk logic yang kompleks (kode harus self-documenting).
- Proper error handling di setiap layer (controller, service, repository).

SOLID PRINCIPLES:
- S (Single Responsibility): Setiap module/class punya satu alasan untuk berubah.
  Contoh: TransactionsService hanya handle logic transaksi, tidak handle auth.
- O (Open/Closed): Gunakan abstract class & interfaces untuk extensibility.
  Contoh: BaseStatementParser bisa di-extend tanpa modifikasi existing code.
- L (Liskov Substitution): Subclass harus bisa menggantikan parent class.
  Contoh: Setiap bank parser bisa digunakan di mana pun BaseStatementParser diharapkan.
- I (Interface Segregation): Interface yang spesifik lebih baik dari yang general.
  Contoh: Pisahkan IReadable dan IWritable daripada satu ICrudRepository besar.
- D (Dependency Inversion): Depend on abstractions, not concretions.
  Contoh: Service depend on repository interface, bukan Prisma client langsung.

TDD (Test-Driven Development):
- Alur: Red → Green → Refactor.
- Unit tests untuk setiap service dan utility function.
- Integration tests untuk setiap controller endpoint.
- E2E tests untuk critical user flows (login, tambah transaksi, upload struk).
- Minimum code coverage target: 80%.
- Mock external dependencies (Prisma, file system, OCR service).
- Test fixtures & factories untuk generate test data.
- Separate test database untuk integration tests.

BACKEND TEST STRUCTURE:
  Setiap module memiliki:
  - *.service.spec.ts    → Unit test service logic
  - *.controller.spec.ts → Unit test controller
  - *.repository.spec.ts → Unit test repository (mock Prisma)
  - test/*.e2e-spec.ts   → Integration test full request-response cycle

FRONTEND TEST STRUCTURE:
  - __tests__/components/ → Component rendering & interaction tests
  - __tests__/hooks/      → Custom hook tests (dengan renderHook)
  - __tests__/lib/        → Utility function tests
  - __tests__/e2e/        → Playwright E2E tests

8. SECURITY CONSIDERATIONS
================================================================================

- Semua password di-hash menggunakan bcrypt (salt rounds: 10-12).
- JWT token dengan expiry time yang reasonable (access: 15 min, refresh: 7 days).
- Refresh token di-hash sebelum disimpan di database.
- HTTP-only, Secure, SameSite cookies untuk refresh token.
- CORS: whitelist hanya frontend domain.
- Rate limiting pada endpoint sensitif (auth, file upload).
- Input validation pada semua endpoint (class-validator).
- SQL injection prevention (Prisma parameterized queries).
- XSS prevention (Next.js default escaping + Content-Security-Policy headers).
- File upload validation:
  - Max file size: 10MB untuk gambar struk, 20MB untuk PDF statement.
  - Allowed MIME types: image/jpeg, image/png, image/heic, application/pdf.
  - Scan file untuk malware (opsional).
- Environment variables untuk semua secrets (JWT_SECRET, DB password, dll).
- Helmet middleware untuk security headers.
- HTTPS enforced di production.

12. CATATAN TAMBAHAN
================================================================================

- Semua response API menggunakan format konsisten:
  {
    "success": true,
    "data": { ... },
    "meta": { "page": 1, "limit": 10, "total": 100, "totalPages": 10 }
  }

  atau untuk error:
  {
    "success": false,
    "error": {
      "code": "VALIDATION_ERROR",
      "message": "Email is required",
      "details": [...]
    }
  }

- Gunakan API versioning (/api/v1/) untuk future-proofing.
- Semua tanggal disimpan dan ditransfer dalam format ISO 8601 (UTC).
- Frontend menampilkan tanggal dalam timezone lokal user (WIB default).
- Semua mata uang dalam Rupiah (IDR), disimpan sebagai Decimal(15,2).
- Pagination default: 10 items per page, max 100.
- File uploads disimpan di local storage (development) atau cloud storage
  seperti AWS S3 / Google Cloud Storage (production).
- Implementasikan proper logging di backend (request/response logging,
  error logging) menggunakan Winston atau Pino.
- Swagger/OpenAPI documentation otomatis dari NestJS decorators, accessible
  di /api/docs.
- Setiap commit mengikuti Conventional Commits format:
  feat: , fix: , docs: , chore: , test: , refactor:
